LEGAL & CLINICAL COMPLIANCE

CareLens Clinical Privacy Notice

Version 1.0.0 | Effective Date: October 22, 2026 | Reference: CL-PRIV-2026-V1
Core Clinical Privacy Guarantee: CareLens processes optical equipment feeds and patient monitor screens entirely on-device at the edge. Raw patient imagery is never uploaded to third-party cloud infrastructure, never retained beyond active frame analysis, and never utilized for machine learning training without explicit institutional consent.

1. Scope and Authority

This Privacy Notice governs all visual stream ingestions, optical telemetry extractions, and clinical evaluation sessions processed through the CareLens Clinical Safety Auditor. This system operates as a clinical decision-support prototype deployed in authorized hospital wards, simulation laboratories, and intensive care environments.

CareLens is engineered for strict adherence to institutional data protection standards, including HIPAA technical safeguards for electronic Protected Health Information (ePHI).

2. Edge Processing Policy

All inference tasks, including vision-language analysis via Gemma 4 and deterministic protocol rule checks, run locally on edge hardware. Image tensors are allocated in volatile system memory (RAM/Unified Memory) for the duration of inference and are purged immediately following response generation.

Network isolation is maintained by default: the application binds locally and does not require outbound internet access to perform vital sign extraction or equipment safety verification.

3. Patient Imagery Handling

CareLens implements strict zero-retention principles for raw visual inputs:

  • No Persistent Image Storage: Still captures and video frames are not saved to disk, object storage, or cloud buckets during routine auditing.
  • No Secondary Utilization: Ingested patient images, monitor screens, and equipment configurations are never repurposed for external model pre-training or public distribution.
  • De-Identification Safeguards: Any authorized reference dataset utilized for test validation must be de-identified in compliance with HIPAA Safe Harbor criteria.

4. Audit Logs and Metadata

To satisfy clinical governance, healthcare quality assurance, and traceability mandates, CareLens maintains an immutable local audit log (audit_trail.jsonl). The audit trail records metadata only and deliberately excludes raw pixel arrays.

Recorded fields are limited to:

  • Unique audit identifier (UUID)
  • UTC ISO 8601 timestamp
  • Inference model identifier and execution runtime environment
  • Active clinical protocol identifier and version string
  • Patient context category (Adult, Pediatric, Neonatal)
  • Inspection category (Equipment_Setup, Patient_Monitor, Unknown)
  • Risk tier result (PASS, WARNING, CRITICAL)
  • Extracted numeric vitals summary and evidence findings
  • Clinician review identifier, timestamp, and verification status

5. Model Execution Governance

The vision model operates within a sandboxed runtime. System prompts explicitly forbid ungrounded speculation regarding patient identity, underlying medical history, or unobserved clinical variables. Where visual quality is degraded, the system is mandated to output WARNING and request human bedside verification.

6. Clinician Verification

CareLens outputs are strictly advisory decision-support aids. The system possesses no autonomous capability or mechanical authorization to modify equipment settings, alter infusion pump rates, or adjust oxygen flow valves. Every safety-critical observation requires physical bedside verification by a qualified clinician.
